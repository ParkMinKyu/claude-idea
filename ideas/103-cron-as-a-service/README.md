# 103 · 크론 작업 호스팅 (Cron as a Service)

## 개요
서버를 직접 운영하지 않고 cron 표현식으로 HTTP 작업을 예약·실행해 주는 호스팅 서비스. 실행 로그, 실패 재시도, 알림을 제공한다. cron-job.org·EasyCron의 개발자 친화적 대안을 지향한다.

## 문제
- 서버리스/PaaS 환경(Vercel, Netlify)에는 신뢰할 수 있는 cron 실행기가 없거나 제한적이다.
- 직접 cron을 운영하면 단일 장애점, 타임존 혼란, 실패 알림 부재 문제가 생긴다.
- 기존 cron SaaS는 실행 로그가 빈약하고 cron 표현식 검증/미리보기가 약하다.

## 솔루션
- 5필드 cron 표현식을 파싱·검증하고 다음 실행 시각 N개를 미리 보여준다(UTC 기준).
- 예약된 시각에 지정한 URL로 HTTP 요청을 발사하고 응답을 기록한다.
- 실패 시 지수 백오프 재시도 + 이메일/Slack 알림.
- "데드맨 스위치"로 작업이 실행되지 않으면 경고(상용판).

## 타겟 사용자
- 서버리스 앱을 운영하는 인디 해커
- 정기 작업(리포트, 캐시 워밍, 백업 트리거)이 필요한 소규모 팀
- cron 인프라를 외주화하려는 스타트업

## 핵심 기능
1. **cron 파서 + 미리보기** — 의존성 없는 5필드 파서, 다음 실행 시각 계산, 잘못된 표현식 즉시 거부
2. **HTTP 잡 디스패처** — 예약 시각에 GET/POST 발사, 헤더/바디 커스텀
3. **실행 로그** — 상태 코드, 응답 시간, 응답 본문 일부 저장
4. **재시도 + 알림** — 지수 백오프 재시도, 실패 알림 채널
5. **타임존 변환** — 사용자 타임존 입력 → UTC 정규화(상용판)

## 수익 모델
오픈코어: cron 파서/스케줄러 코어는 MIT, 호스팅 실행·로그·알림은 SaaS.

| 플랜 | 가격 | 작업 수 | 최소 주기 | 로그 보관 |
|---|---|---|---|---|
| OSS (self-host) | $0 | 무제한 | 1분 | 직접 DB |
| Free | $0 | 5 | 10분 | 24시간 |
| Pro | $9/월 | 50 | 1분 | 30일 + 알림 |
| Business | $39/월 | 500 | 1분 | 90일 + 데드맨 스위치 |

## 사용 시나리오
1. 사용자가 cron 표현식과 호출할 URL/메서드를 입력한다.
2. 입력 즉시 다음 5회 실행 시각이 미리보기로 표시된다(실수 방지).
3. 예약 시각마다 서비스가 URL을 호출하고 응답을 로그에 기록한다.
4. 실패 시 지수 백오프로 재시도하고 이메일/Slack으로 알린다.
5. 실행이 누락되면 데드맨 스위치가 경고를 보낸다(Business).

## 경쟁사
- **cron-job.org** — 무료/단순하나 로그·알림 빈약
- **EasyCron** — 기능 많으나 UI 노후, 미리보기 약함
- **Cronitor** — 모니터링 강점, 작업 호스팅은 부가
- **Vercel Cron** — 플랫폼 종속, 최소 주기 제한
- **GitHub Actions schedule** — 지연·신뢰성 이슈, 범용 잡 부적합

## 차별점
- cron 표현식 미리보기(다음 N회 실행 시각)를 입력 단계에서 제공해 실수 방지
- 파서/스케줄러 코어가 의존성 0 → 셀프호스팅 신뢰성·감사 용이
- 데드맨 스위치(실행 누락 감지)를 cron SaaS에 통합
- 실행 로그에 응답 본문 일부를 보관해 디버깅 지원

## KPI
- 첫 작업 생성 후 첫 성공 실행까지 시간 < 5분
- cron 미리보기 사용률(입력 정확도 향상 지표)
- 작업 실행 정시성: 예약 대비 지연 < 5초 P95
- Free → Pro 전환율 5% 이상
- 작업 실행 성공률 99.9% 이상
