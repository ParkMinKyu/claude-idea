# 137 · Webhook Relay (로컬 웹훅 터널)

## 개요
공개 URL로 들어온 웹훅을 방화벽 뒤의 로컬 개발 환경으로 안전하게 전달하는
ngrok 류 터널 서비스입니다. 핵심은 터널 레지스트리 + 메시지 라우팅 + 재생(replay)
버퍼입니다. 로컬 에이전트가 잠시 끊겨도 링 버퍼에 쌓인 메시지를 재연결 시 다시
받을 수 있습니다. 라우팅 코어는 전송 계층과 무관한 순수 로직입니다.

## 문제
- Stripe/GitHub/Slack 등 웹훅을 로컬에서 디버깅하려면 공개 URL이 필요합니다.
- 개발 중 서버 재시작·네트워크 끊김으로 웹훅 이벤트를 놓치기 쉽습니다.
- 동일 이벤트를 반복 재현(replay)하기 어렵습니다.
- 들어온 요청을 여러 로컬 타깃으로 라우팅하는 규칙 설정이 번거롭습니다.

## 솔루션
공개 ingest 엔드포인트로 받은 요청을 구독 중인 로컬 에이전트에 팬아웃하고,
링 버퍼로 재생/재현을 지원합니다. 경로 기반 라우팅 규칙(prefix/regex + rewrite)으로
여러 로컬 서비스로 분기할 수 있습니다.

## 타겟 사용자
- 결제/메신저/SCM 웹훅을 통합하는 백엔드 개발자
- 통합(integration)을 빌드하는 SaaS 팀
- 데모/QA에서 외부 콜백을 받아야 하는 팀

## 핵심 기능
1. 공개 URL ↔ 로컬 에이전트 터널링 (SSE/WebSocket)
2. 다중 구독자 팬아웃 (한 구독자 실패가 전체를 막지 않음)
3. 링 버퍼 기반 재생/재연결 복구 (afterSeq replay)
4. 경로 기반 라우팅 규칙 (prefix/regex + rewrite)
5. 터널 통계 (버퍼/구독자/시퀀스)

## 수익 모델 (가격 티어)
- Free: 1 터널, 랜덤 서브도메인, 1시간 세션
- Pro ($10/월): 예약 서브도메인, 무제한 세션, 재생 7일 보관
- Team ($40/월): 팀 공유 터널, 라우팅 규칙, 5인 좌석
- Enterprise (협의): 셀프호스트, 커스텀 도메인, 감사 로그

## 경쟁사
- ngrok (시장 표준, 범용 터널)
- Cloudflare Tunnel (인프라 중심)
- smee.io / webhook.site (단순 무료 도구)

## 차별점
- 재생 버퍼로 끊김에도 이벤트 손실 없이 복구
- 경로 라우팅+rewrite로 멀티 로컬 서비스 분기
- 전송 계층과 분리된 순수 라우팅 코어로 셀프호스트 용이
- 웹훅 디버깅 UX(검사/재전송)에 특화

## KPI
- 활성 터널 수, 일 전달 메시지 수
- 재연결 복구로 회수된 이벤트 수
- Free→Pro 전환율, 예약 서브도메인 사용률
- 팀 공유 터널 채택 수
