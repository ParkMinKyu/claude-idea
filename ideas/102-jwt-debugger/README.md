# 102 · JWT 디코더/검증기

## 개요
JWT를 브라우저에서 디코딩·검증하고 표준 클레임(exp, nbf, iss, aud)을 분석하는 개발자 도구. 토큰이 서버로 전송되지 않는 "클라이언트 사이드 디코드"가 핵심이다. jwt.io의 프라이버시 강화형 대안을 지향한다.

## 문제
- 개발자는 디버깅을 위해 운영 토큰을 jwt.io 같은 외부 사이트에 붙여넣는 경우가 많은데, 이는 민감 정보 유출 위험이 있다.
- 서명 검증이 실패하는 원인(잘못된 알고리즘, 시크릿 인코딩, 만료)을 빠르게 진단하기 어렵다.
- 팀 환경에서 JWKS 엔드포인트 기반 검증을 반복 수행할 도구가 부족하다.

## 솔루션
- 디코딩은 100% 브라우저에서 수행 — 토큰이 네트워크를 떠나지 않는다.
- exp/nbf/iat를 현재 시각과 비교해 활성/만료/미발효 상태와 잔여 TTL을 표시한다.
- HS256(시크릿), RS/ES(SPKI PEM), JWK/JWKS 기반 서명 검증을 jose로 수행한다.
- 검증 실패 시 jose 오류 코드를 그대로 노출해 원인 진단을 돕는다.

## 타겟 사용자
- 인증/인가를 다루는 백엔드·프론트엔드 개발자
- OAuth/OIDC 통합을 디버깅하는 플랫폼 엔지니어
- 보안상 외부 도구 사용이 금지된 조직

## 핵심 기능
1. **클라이언트 사이드 디코드** — base64url 세그먼트를 파싱, 시크릿 없이 헤더/페이로드 표시
2. **클레임 인스펙터** — exp/nbf/iat 시간 검증, iss/aud/sub 추출, 사람이 읽을 수 있는 노트
3. **멀티 키 검증** — 시크릿/PEM/JWK, jose 표준 라이브러리 사용
4. **JWKS 가져오기** — 발급자의 JWKS URL에서 키를 받아 kid 매칭(상용판)
5. **토큰 생성기** — 디버깅용 테스트 토큰 서명(상용판)

## 수익 모델
오픈코어: 디코드/검증 코어는 MIT, 팀 협업·JWKS 캐시·감사 기능은 상용.

| 플랜 | 가격 | 검증 방식 | JWKS | 팀 |
|---|---|---|---|---|
| OSS (self-host) | $0 | 전체 | 수동 | - |
| Free (web) | $0 | 디코드 + HS/RS 검증 | - | 1명 |
| Pro | $8/월 | 전체 + 토큰 생성 | JWKS URL 캐시 | 1명 |
| Team | $29/월 | 전체 | 공유 JWKS 프리셋 | 10명 + SSO |

## 사용 시나리오
1. 개발자가 디버깅 중인 JWT를 붙여넣는다(브라우저 내 처리).
2. 헤더/페이로드가 즉시 디코딩되고 exp/nbf/iat 상태가 표시된다.
3. 시크릿 또는 공개키(PEM/JWK)를 입력해 서명을 검증한다.
4. 검증 실패 시 jose 오류 코드로 원인(알고리즘/만료/시크릿)을 파악한다.
5. 필요 시 JWKS URL을 등록해 kid 매칭으로 자동 검증한다(Pro).

## 경쟁사
- **jwt.io(Auth0)** — 사실상 표준이나 토큰을 페이지에 입력(프라이버시 우려)
- **token.dev** — 디코드/생성 지원, 팀 기능 없음
- **jwt.ms(Microsoft)** — Azure AD 토큰 중심, 검증 약함
- **jwtdecode.com** — 단순 디코드, 검증 기능 부족

## 차별점
- 디코딩이 완전히 클라이언트 사이드 → 운영 토큰 유출 위험 제거(주요 셀링 포인트)
- 정적 사이트로 배포 가능해 사내 인트라넷 셀프호스팅 용이
- jose 기반 정확한 알고리즘 지원(ES256K, EdDSA 포함)
- 검증 실패 사유를 표준 오류 코드로 명시

## KPI
- 디코드 → 검증 시도 전환율 30% 이상 (핵심 가치 사용 비율)
- 평균 세션 시간 및 재방문율(개발 도구 stickiness)
- OSS Star 수 및 셀프호스팅 배포 수
- Free → Pro 전환율 3% 이상
- 클라이언트 사이드 처리 비율 100% 유지(프라이버시 약속 검증)
