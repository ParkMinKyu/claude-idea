# 139 · Commit Lint (커밋 메시지 컨벤션 검사)

## 개요
Conventional Commits 규칙에 맞게 커밋 메시지를 파싱하고 검증하는 도구입니다.
`type(scope?): subject` 헤더, 본문, 푸터(BREAKING CHANGE 등)를 구조화해 파싱하고,
타입 화이트리스트·헤더 길이·scope 필수 여부 등 규칙으로 검사합니다. commit-msg
훅이나 CI에 붙여 일관된 커밋 이력을 강제할 수 있습니다.

## 문제
- 커밋 메시지가 제각각이면 변경 이력 파악과 릴리스 노트 자동화가 어렵습니다.
- 팀마다 다른 규칙을 일관되게 적용·검증하기 번거롭습니다.
- 잘못된 타입/형식이 머지된 뒤에야 발견됩니다.
- 자동 버전 결정(semantic-release)에는 정확한 형식이 필수입니다.

## 솔루션
헤더/본문/푸터를 정밀 파싱하고 규칙으로 검증하며, 위반 시 한국어 메시지로
구체적인 수정 지침을 제공합니다. 머지 커밋은 자동 스킵하고, 경고/오류를 구분해
점진적 도입이 가능합니다.

## 타겟 사용자
- 일관된 커밋 컨벤션을 원하는 개발팀
- semantic-release/자동 changelog를 쓰는 프로젝트
- 오픈소스 메인테이너(기여자 PR 품질 관리)

## 핵심 기능
1. Conventional Commits 파서 (type/scope/subject/body/footer)
2. BREAKING CHANGE 탐지 (`!` 및 푸터)
3. 규칙 검사 (타입 화이트리스트, 길이, scope 필수, 케이스)
4. 오류/경고 구분 + 한국어 가이드 메시지
5. commit-msg 훅 / CI exit code 연동

## 수익 모델 (가격 티어)
- Free / OSS: CLI·훅 무료, 기본 규칙
- Pro ($5/개발자/월): 팀 공유 규칙셋, CI 리포트, 커스텀 타입
- Team ($29/월): 조직 정책, PR 코멘트 봇, 통계 대시보드
- Enterprise (협의): 셀프호스트, 감사, SSO

## 경쟁사
- commitlint (오픈소스 표준)
- gitlint (Python)
- 각종 husky + 자체 스크립트 조합

## 차별점
- 한국어 친화 가이드 메시지로 도입 장벽 완화
- 파서/규칙을 순수 함수로 분리해 CI·봇·엣지 재사용
- 경고/오류 분리로 점진 도입 지원
- 머지/리버트 자동 인식으로 노이즈 감소

## KPI
- 검사된 커밋 수, 차단된 위반 수
- 훅/CI 통합 리포지토리 수
- Free→Pro 전환율, 팀 규칙셋 채택 수
- 도입 후 changelog 자동화 성공률
