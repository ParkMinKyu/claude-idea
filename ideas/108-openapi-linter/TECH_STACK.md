# Tech Stack · 108 OpenAPI Linter

## 언어/런타임
- **Node.js 20** — CLI + 라이브러리 + 서버리스 API에 모두 적합
- **ESM** — 트리셰이킹 친화, `bin`으로 CLI 노출

## 규칙 엔진
- **순수 JS 함수 규칙** — `check(spec) -> issues[]`. Spectral의 JSONPath DSL 대신 일반 함수를 채택해 학습 곡선 제거·디버깅 용이
- 규칙 메타데이터(id/severity/description)로 선택·비활성화·요약 지원
- 의존성 0 코어 → 빠른 실행, 공급망 보안

## 스펙 파싱
- 입력은 이미 파싱된 객체(JSON). YAML 입력은 상용에서 **yaml** 패키지로 전처리
- `$ref` 해석은 상용 플랜에서 번들러 단계로 추가(코어는 단일 문서 검증)

## CLI
- 종료 코드: error 존재 시 1, 정상 0, 사용오류 2 → CI 게이트로 활용
- 파일 읽기를 주입 가능하게 설계해 오프라인 테스트

## 통합(상용)
- **GitHub Action** — PR에서 자동 lint + 인라인 코멘트
- 거버넌스 대시보드(Next.js)로 조직 규칙 정책 관리

## 데이터/과금(상용)
- **PostgreSQL** — 규칙 정책, lint 이력
- **Stripe Billing** — 구독

## 테스트
- **Vitest** — 유효 스펙(이슈 0), operationId 중복/누락, 2xx 누락, 경로 파라미터 미선언, 규칙 선택, 메타데이터 무결성
- 파일 리더 주입으로 CLI 로직까지 오프라인 검증

## 선택 이유 요약
확장성과 접근성을 위해 규칙을 DSL이 아닌 순수 함수로 설계했다. 의존성 0 코어로 CLI/CI/엣지 어디서나 빠르게 돌고, 사용자가 자신의 규칙을 쉽게 추가·테스트할 수 있다.
