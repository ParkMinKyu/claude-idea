# 112 · 실시간 로그 뷰어/필터

## 개요
표준입력으로 흘러드는 로그를 실시간으로 파싱하고, 간결한 필터 DSL로 즉시 걸러내는
경량 로그 뷰어입니다. JSON 로그와 일반 텍스트 로그를 모두 인식하며, 코어 파서와 필터는
순수 함수로 분리되어 CLI/웹/엣지에서 동일하게 동작합니다.

## 문제
- `grep`/`jq` 조합은 강력하지만 레벨 임계값, 필드 일치, 부정 조건을 한 줄로 표현하기 번거롭습니다.
- 무거운 로그 SaaS(예: Datadog)는 작은 팀이나 로컬 디버깅에 과합니다.
- JSON 로그와 텍스트 로그가 섞이면 일관된 필터링이 어렵습니다.

## 솔루션
- 로그 라인을 `LogEntry`(ts/level/message/fields)로 정규화하는 파서.
- `level>=warn user=alice -healthcheck` 같은 직관적 필터 DSL(암묵적 AND, 부정, 필드 일치).
- 스트리밍 CLI로 `tail -f | log-viewer "..."` 패턴 지원.

## 타겟 사용자
- 백엔드 개발자, SRE, DevOps
- 로컬/스테이징에서 빠른 디버깅이 필요한 소규모 팀
- 로그 SaaS 도입 전 단계의 스타트업

## 핵심 기능
1. 다형 로그 파서 — JSON / `ts LEVEL msg key=value` 텍스트 자동 인식.
   - JSON 실패 시 텍스트 파서로 폴백, 미구조 라인은 raw 메시지로 보존.
2. 필터 DSL — 레벨 임계값(`level>=warn`), 필드 일치(`user=alice`), 텍스트, 부정(`-term`).
   - 공백 구분 항목은 암묵적 AND, 따옴표로 다중 단어 텍스트 매칭.
3. 레벨 정규화 — `warning→warn` 등 표준화 후 임계값 비교.
4. 스트리밍 CLI — 표준입력 라인 단위 처리, 백프레셔 친화적.
5. 순수 코어 — 동일 로직을 웹 뷰어/엣지 함수에서 재사용.

## 사용 예시
```bash
# 실시간 테일 + 필터
tail -f app.log | npm run view -- "level>=warn -healthcheck"

# 특정 유저의 에러만
cat app.log | node src/index.ts "level:error user=alice"
```
파서(`src/lib/parser.ts`)와 필터(`src/lib/filter.ts`)는 순수 함수라 웹 뷰어에서도 그대로 임포트합니다.

## 도입 시나리오
- 로컬 디버깅에서 grep/jq 대신 한 줄 DSL로 빠른 필터링.
- 스테이징 서버 로그를 SSH 파이프로 실시간 모니터링.
- 웹 라이브 테일 UI(Pro)로 팀이 동일 필터를 공유.

## 수익 모델
- 오픈코어: 파서 + 필터 DSL + CLI는 MIT 오픈소스.
- SaaS Pro 가격 티어:
  - Free: 로컬 CLI, 무제한.
  - Pro ($9/월): 웹 라이브 테일 UI, 저장된 필터, 7일 보관.
  - Team ($29/월): 멀티소스 수집, 알림 규칙, 30일 보관, 공유 대시보드.

## 경쟁사
- lnav — 강력한 TUI지만 DSL 학습 곡선이 있고 웹 공유 불가.
- GoAccess — 웹 로그 특화, 일반 앱 로그엔 부적합.
- Datadog Logs / Papertrail — 강력하지만 비싸고 데이터 외부 전송.
- Grafana Loki — 인프라 구축 부담이 큼.

## 차별점
- 의존성 0 코어로 어디서나 동일한 필터 동작(로컬↔클라우드 일관성).
- 학습 비용이 낮은 한 줄 DSL — grep/jq보다 표현력 높고 SaaS보다 가벼움.
- JSON/텍스트 혼합 로그를 같은 쿼리로 처리.
- 로컬 CLI에서 시작해 웹/팀 협업으로 자연 확장되는 업그레이드 경로.

## KPI
- CLI 일일 처리 라인 수, 활성 사용자 수.
- 저장된 필터 수(웹 전환 신호), Free→Pro 전환율.
- 멀티소스 수집 연결 수(Team 가치 지표).
- 평균 필터 쿼리 복잡도(DSL 활용도 지표).
