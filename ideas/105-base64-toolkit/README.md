# 105 · 인코딩/디코딩 멀티툴

## 개요
base64, base64url, hex, URL 퍼센트 인코딩을 상호 변환·검증하는 멀티툴. 입력 포맷 자동 감지와 클라이언트 사이드 처리를 제공한다. 흔한 base64 온라인 도구들의 통합·프라이버시 강화형 대안을 지향한다.

## 문제
- base64/hex/URL 인코딩을 다루는 온라인 도구가 파편화되어 있어 매번 다른 사이트를 찾아야 한다.
- base64와 base64url의 차이(+/ vs -_)로 디코딩이 실패하는 일이 잦은데, 에러 원인을 알려주지 않는다.
- 민감 데이터(토큰, 페이로드)를 외부 사이트에 붙여넣는 보안 위험이 있다.

## 솔루션
- 4개 포맷을 하나의 도구에서 인코딩/디코딩하고 임의 포맷 간 변환한다.
- 입력 문자열의 포맷을 자동 감지해 실수를 줄인다.
- 잘못된 입력(홀수 길이 hex, 비허용 문자)을 명확한 에러로 거부한다.
- 모든 변환을 브라우저에서 수행해 데이터가 서버로 전송되지 않는다.

## 타겟 사용자
- API/토큰을 디버깅하는 백엔드 개발자
- 데이터 포맷을 자주 변환하는 데이터 엔지니어
- 보안상 외부 도구가 금지된 환경의 개발자

## 핵심 기능
1. **멀티 포맷 코덱** — base64 / base64url / hex / URL 인코딩·디코딩
2. **포맷 자동 감지** — 입력 패턴으로 가장 가능성 높은 포맷 추정
3. **포맷 간 변환** — 평문 경유 라운드트립으로 임의 포맷 ↔ 포맷
4. **검증 + 에러 메시지** — 비허용 문자/길이 오류를 사유와 함께 거부
5. **UTF-8 안전** — 한글·이모지 등 멀티바이트 무손실 처리

## 사용 시나리오
1. 개발자가 API 응답의 base64 문자열을 붙여넣는다.
2. 도구가 포맷을 자동 감지(base64/base64url/hex/url)해 알려준다.
3. decode 모드로 평문을 확인하고, 필요 시 다른 포맷으로 변환한다.
4. 잘못된 입력이면 구체적 에러(홀수 길이 hex 등)를 표시한다.
5. 모든 처리가 브라우저에서 일어나 민감 데이터가 전송되지 않는다.

## 경쟁사
- **base64encode.org / base64decode.net** — 단일 포맷, 감지/변환 없음
- **CyberChef(OSS)** — 강력하나 복잡, 단순 변환엔 과함
- **urlencoder.org** — URL 인코딩 전용
- 대부분 비ASCII(한글/이모지)에서 깨지거나 조용히 실패

## 차별점
- 4개 포맷 + 자동 감지 + 포맷 간 변환을 단일 화면에서 제공
- 100% 클라이언트 사이드 → 민감 데이터 유출 없음
- 에러 사유를 명확히 표시(경쟁사는 조용히 실패하거나 깨진 출력)
- UTF-8 멀티바이트 무손실(많은 도구가 비ASCII에서 깨짐)
