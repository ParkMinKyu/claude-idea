# 108 · OpenAPI 스펙 검증기

## 개요
OpenAPI 3.x 스펙을 규칙 엔진으로 검사해 일관성·완성도·모범사례 위반을 찾아내는 린터. CLI/API/CI로 통합 가능하다. Spectral의 가볍고 확장하기 쉬운 대안을 지향한다.

## 문제
- 수기로 작성·생성된 OpenAPI 스펙은 operationId 누락/중복, 응답 누락, 경로 파라미터 미선언 같은 결함이 흔하다.
- 이런 결함은 코드 생성기·문서·SDK를 깨뜨리지만 런타임 전까지 드러나지 않는다.
- Spectral 같은 도구는 강력하지만 규칙 작성/설정이 무겁고 학습 곡선이 있다.

## 솔루션
- 파싱된 스펙 객체에 규칙 함수들을 적용하는 가벼운 규칙 엔진을 제공한다.
- 핵심 규칙(operationId 유일성, 2xx 응답 존재, 경로 파라미터 선언, contact 정보)을 기본 탑재한다.
- error/warn 심각도로 분류하고 CI에서 error 시 종료 코드 1을 반환한다.
- 규칙은 순수 함수라 사용자가 손쉽게 커스텀 규칙을 추가할 수 있다.

## 타겟 사용자
- API 퍼스트로 개발하는 백엔드 팀
- SDK/문서를 OpenAPI에서 생성하는 플랫폼 팀
- API 거버넌스를 CI에 강제하려는 조직

## 핵심 기능
1. **규칙 엔진** — `{ id, severity, check(spec) }` 구조의 플러그형 규칙
2. **기본 규칙 세트** — operationId 유일성, 2xx 응답, 경로 파라미터 선언, contact
3. **심각도 분류 + 요약** — error/warn 집계, CI 종료 코드
4. **CLI** — `openapi-lint spec.json`, 규칙 선택/비활성화
5. **커스텀 규칙** — 순수 함수로 조직별 규칙 추가(상용판: 규칙 마켓플레이스)

## 수익 모델
오픈코어: 엔진 + 기본 규칙은 MIT, 거버넌스 대시보드·규칙팩·CI 통합은 SaaS.

| 플랜 | 가격 | 규칙 | 통합 | 팀 |
|---|---|---|---|---|
| OSS | $0 | 기본 + 커스텀 | CLI | - |
| Free | $0 | 기본 | GitHub Action | 1 repo |
| Pro | $29/월 | + 프리미엄 규칙팩 | + PR 코멘트 | 10 repo |
| Enterprise | 협의 | + 조직 규칙 정책 | + 대시보드/감사 | 무제한 + SSO |

## 사용 시나리오
1. 팀이 `openapi-lint spec.json`을 CI 파이프라인에 추가한다.
2. PR마다 스펙을 검사해 error가 있으면 빌드를 실패시킨다.
3. 개발자는 위반 위치(paths.x.get)와 사유를 즉시 확인한다.
4. 조직 규칙이 필요하면 순수 함수 규칙을 직접 추가한다.
5. 거버넌스 가시화를 위해 대시보드로 전환한다(Enterprise).

## 경쟁사
- **Spectral(Stoplight)** — 강력하나 JSONPath DSL 학습 곡선, 설정 무거움
- **Redocly CLI** — 문서 중심, 린트는 부가
- **Vacuum** — 빠르나 규칙 커스터마이즈가 Go 의존
- **openapi-validator(IBM)** — 무겁고 IBM 생태계 지향

## 차별점
- 규칙이 순수 JS 함수 → JSONPath 기반 DSL 학습 불필요, 디버깅 쉬움
- error/warn + CI 종료 코드로 거버넌스 강제가 기본
- 가벼운 코어(의존성 0)로 빠른 실행과 셀프호스팅
- PR 코멘트로 위반 위치를 인라인 표시(상용판)

## KPI
- CLI 실행 수 및 CI 통합 repo 수
- 위반 탐지 정확도(false positive < 1%)
- Free → Pro 전환율 5% 이상
- OSS Star → SaaS 전환율
- 평균 lint 실행 시간 < 200ms(중형 스펙)
